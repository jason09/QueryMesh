Node.js query builder and light ORM

One fluent API for SQL and MongoDB.

QueryMesh is a compact multi-dialect query builder for Node.js. It targets PostgreSQL, MySQL, SQL Server, Oracle, MongoDB, and Mongoose-backed connections with a practical, readable builder style.

Install

Install QueryMesh, then install only the driver packages you actually use.

Core package 
npm install querymesh
Dialect drivers 
npm install pg
npm install mysql
npm install mssql
npm install oracledb
npm install mongodb

Connect

The root entry point is QueryMesh.connect(...). Dialects can use connection strings or structured config where supported.

PostgreSQL 
import QueryMesh from "querymesh";

const db = await QueryMesh.connect({
  dialect: "pg",
  config: {
    server: "localhost",
    user: "postgres",
    password: "postgres",
    database: "app",
    port: 5432,
  },
});
MongoDB 
const db = await QueryMesh.connect({
  dialect: "mongo",
  config: {
    connectionString: "mongodb://localhost:27017/app",
    options: { maxPoolSize: 20 },
  },
});
Pool behavior: Create one shared DB instance and reuse it. PostgreSQL, MySQL, SQL Server, and Oracle use driver pools internally. MongoDB uses a single MongoClient with its own internal pool. Mongoose reuses the existing Mongo connection. Query builder calls and db.query(...) use the same pool/client, and db.transaction(...) borrows a dedicated connection/session until commit or rollback. db.close() closes the underlying pool/client.

Query builder

Build readable queries with db.table(name). Use get() for select results and run() for mutations.

Readable select

Use chainable methods for filters, sorting, offsets, limits, and projections.

Grouped where

Use callback groups when boolean logic needs explicit parentheses.

Raw SQL

Use raw(...), selectRaw(...), or selectExpr(...) for trusted SQL expressions inside the builder.

Full SQL

Use db.query(...) for full SQL statements. It exposes .rows and .rowCount.

Aliased joins

Use join...As helpers when the same table or collection is joined more than once.

Select 
const users = await db
  .table("users")
  .select(["id", "email"])
  .where("is_active", true)
  .orderBy("id", "desc")
  .limit(20)
  .get();
Grouped where 
const rows = await db
  .table("users")
  .where((q) => q.where("a", x).where("b", y))
  .orWhere((q) => q.where("c", z).orWhere("d", xx))
  .get();
Raw SQL fragment 
import { raw } from "querymesh";

const rows = await db
  .table("users")
  .select("id")
  .selectExpr("LOWER(email)", "email_lower")
  .where(raw("LOWER(email)"), "alice@example.com")
  .get();
Full SQL query 
const result = await db.query(
  "SELECT id, email FROM users WHERE id = ?",
  [userId]
);

console.log(result.rows);
console.log(result.rowCount);

const updateResult = await db.query(
  "UPDATE users SET active = ? WHERE id = ?",
  [false, userId]
);

console.log(updateResult.rowCount);
raw vs query 
// raw(...) is only a SQL fragment inside a builder
await db.table("users")
  .where(raw("LOWER(email)"), email.toLowerCase())
  .get();

// query(...) executes the whole SQL statement directly
const result = await db.query(
  "SELECT * FROM users WHERE LOWER(email) = ?",
  [email.toLowerCase()]
);

console.log(result.rows);
Aliased joins 
const rows = await db
  .table("tickets")
  .leftJoinOnAs("users", "creator", "tickets.created_by", "creator.id")
  .leftJoinOnAs("users", "assignee", "tickets.assigned_to", "assignee.id")
  .select(["tickets.id", "tickets.title", "creator.name", "assignee.name"])
  .get();
Multiple ON conditions 
// LEFT JOIN A ON B.X = A.X AND B.Y = A.Y
const rows = await db
  .table("B")
  .leftJoinOn("A", "B.X", "A.X")
  .andOn("B.Y", "A.Y")
  .get();
Insert returning 
const [post] = await db
  .table("posts")
  .insert({
    title: payload.title,
    body: payload.body,
    author_id: payload.authorId,
    public_token: payload.publicToken,
    created_at: new Date(),
    updated_at: new Date(),
  })
  .returning(["id", "title", "author_id", "public_token", "created_at"])
  .run();

Mongo ObjectId helpers

QueryMesh keeps Mongo values explicit. Use the ObjectId helpers when filtering by _id or ObjectId reference fields.

toObjectId(...) lazy-loads the MongoDB driver. toObjectIdSync(...) does not import anything, so pass the ObjectId constructor yourself.

ObjectId 
import { ObjectId } from "mongodb";
import QueryMesh, { toObjectIdSync } from "querymesh";

const id = toObjectIdSync(rawId, ObjectId);

const user = await db
  .table("users")
  .where("_id", id)
  .first();

const asyncId = await QueryMesh.toObjectId(rawId);

Model layer

Use BaseModel when you want an ORM-style layer over the same query builder.

Define model 
import { BaseModel } from "querymesh";

class User extends BaseModel {
  static table = "users";
  static primaryKey = "id";
}

const UserModel = db.model(User);
Use model 
const user = await UserModel.create({
  email: "alice@example.com",
  role: "admin",
});

const first = await UserModel
  .query()
  .where("email", "alice@example.com")
  .first();

Dialect support

QueryMesh keeps a consistent API, but each database still has its own capabilities.

Feature SQL dialects MongoDB Notes
Select, insert, update, delete Yes Yes Mongo compiles to native driver operations.
Joins Native SQL joins $lookup and $unwind Alias joins map to $lookup.as for stable output keys.
returning(...) PostgreSQL and SQL Server Best effort MySQL and Oracle do not have the same native behavior.
Functions Supported on pg/mysql/mssql/oracle No createFunction/dropFunction are SQL-only and routine bodies stay dialect-specific.
Procedures Supported on pg/mysql/mssql/oracle No createProcedure/dropProcedure plus db.call(...) for simple execution.
Table-valued / set-returning functions pg, mssql, oracle No Use db.callTable(...) when the routine returns rows.
Raw select expressions Yes No Use selectRaw(...) or selectExpr(...) for trusted SQL expressions in the select list.
Custom aggregate objects PostgreSQL only No createAggregate/dropAggregate are advanced PostgreSQL-only schema helpers, not part of normal query-time aggregation.
PostgreSQL types PostgreSQL only No createType/dropType support enum, composite, and low-level PostgreSQL type definitions.
Catalog helpers showSchemas/showConstraints on pg/mysql/mssql/oracle; showSequences on pg/mssql/oracle No MySQL has no portable sequence objects, so showSequences() is not supported there.
Views and triggers Supported where the dialect supports them No MongoDB does not support SQL triggers or SQL views in QueryMesh.
Maintenance helpers truncateTable on all SQL dialects; analyzeTable on all SQL dialects; optimizeTable on pg/mysql/mssql; vacuumTable on pg; reindexTable on pg/mssql; repairTable on mysql truncateTable only Mongo truncateTable deletes all documents. optimizeTable is a best-effort SQL mapping, not identical behavior across dialects. PostgreSQL VACUUM helpers cannot run inside a transaction block.
Schema introspection Tables, columns, views, triggers, indexes, create SQL Collections, view collections, indexes, sampled structure Use showViews, showTriggers, showIndexes, and schema().getDesc(...) for normalized descriptions.
