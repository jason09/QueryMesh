This page documents the public QueryMesh API by module. Examples assume an existing db instance created with QueryMesh.connect(...).

QueryMesh root

The root module creates connections and exposes helpers for raw SQL, safe identifiers, and Mongo ObjectId conversion.

connect(options)

connect({ dialect, config, features?, importer? }): Promise<DB>

Creates a connected DB instance for pg, mysql, mssql, oracle, mongo, mongodb, or mongoose.

Example
import QueryMesh from "querymesh";

const db = await QueryMesh.connect({
  dialect: "pg",
  config: {
    server: "localhost",
    user: "postgres",
    password: "postgres",
    database: "app",
    port: 5432,
  },
});

raw(sql, params?)

raw(sql: string, params?: any[]): Raw

Creates a raw SQL fragment or raw source for places where QueryMesh accepts raw expressions. Use it when the fragment should be inserted into generated SQL instead of quoted as an identifier or bound as a plain value.

Use raw(...) sparingly and only with trusted SQL fragments. Keep user input as normal QueryMesh values whenever possible.

For full manual SQL execution, use db.query(...) instead of raw(...).

Rule of thumb: raw(...) is part of a generated QueryMesh query; db.query(...) is the whole SQL query.

Example
import { raw } from "querymesh";

const user = await db
  .table("users")
  .where(raw("LOWER(email)"), "alice@example.com")
  .first();

await db
  .table("posts")
  .update({ updated_at: raw("CURRENT_TIMESTAMP") })
  .where("id", postId)
  .run();

id(name)

id(name: string): Identifier

Marks a value as an identifier instead of a normal value. Use it when a method accepts identifier helpers.

Example
import { id } from "querymesh";

const quoted = db.quote(id("users.email").name);

toObjectId(value, opts?)

toObjectId(value, { ObjectId?, importer? }?): Promise<any>

Converts strings or Extended JSON { $oid } values to MongoDB ObjectId. It lazy-loads mongodb unless you pass an ObjectId constructor.

Example
import { toObjectId } from "querymesh";

const id = await toObjectId("507f1f77bcf86cd799439011");
const user = await db.table("users").where("_id", id).first();

toObjectIdSync(value, ObjectId)

toObjectIdSync(value: any, ObjectId: constructor): any

Synchronous ObjectId conversion. It does not import anything; pass the constructor from mongodb or Mongoose.

Example
import { ObjectId } from "mongodb";
import { toObjectIdSync } from "querymesh";

const id = toObjectIdSync(payload.userId, ObjectId);

DB

The DB instance is the main runtime object returned by connect(...).

Method What it does Example
table(name) Starts a QueryBuilder for a table or collection. db.table("users").where("active", true).get()
query(sql, params?) Executes full raw SQL and returns a rows array with .rows and .rowCount. SQL dialects only. Portable ? placeholders are rewritten for the current dialect. await db.query("SELECT * FROM users WHERE id = ?", [id])
raw(sql, params?) Convenience wrapper around root raw(...). db.raw("CURRENT_TIMESTAMP")
id(name) Convenience wrapper around root id(...). db.id("users.email")
quote(name) Quotes an identifier for the current dialect. db.quote("users.email")
schema() Starts schema/DDL/introspection operations. db.schema().showTables()
backup() Starts import/export operations using native CLI tools. db.backup().export({ file: "dump.sql" })
tools() Returns runtime and CLI diagnostics helper. await db.tools().getDiagnostics()
switchDatabase(name, opts?) Switches the current DB instance to another database. await db.switchDatabase("app_b")
useDatabase(name, opts?) Alias of switchDatabase(...). await db.useDatabase("app_c")
switchDialect(dialect, config, opts?) Reconnects the same DB object to another dialect. await db.switchDialect("mongo", { connectionString })
useDialect(dialect, config, opts?) Alias of switchDialect(...). await db.useDialect("pg", pgConfig)
transaction(fn) Runs work inside a transaction/session where supported. await db.transaction(async (trx) => trx.table("logs").insert(row).run())
model(ModelClass) Binds a BaseModel subclass to the current DB. const User = db.model(UserModel)
close() Closes the underlying pool/client when supported. await db.close()
Transaction example
await db.transaction(async (trx) => {
  await trx.table("accounts").update({ balance: 90 }).where("id", 1).run();
  await trx.table("accounts").update({ balance: 110 }).where("id", 2).run();
});

QueryBuilder

The fluent builder powers selects, joins, filters, aggregates, set operations, and mutations.

Selection

select, distinct, aggregate, count, sum, avg, min, max, clearAggregates

Choose returned columns and aggregate values.

Example
const stats = await db
  .table("orders")
  .select("status")
  .count("*", "total")
  .min("amount", "min_amount")
  .max("amount", "max_amount")
  .groupBy("status")
  .get();

Filtering

where, orWhere, whereOp, whereGroup, orWhereGroup, whereNot, orWhereNot

Build basic and grouped boolean filters. Callback groups compile explicit parentheses for SQL and preserve logic for Mongo.

where("field", value) means equality. Use whereOp("field", ">", value) when you need a custom operator. Use orWhere(...) to start an OR branch.

where((q) => ...) is the same idea as whereGroup(...): it creates parentheses around the nested conditions. whereNot((q) => ...) creates NOT (...).

Example
const rows = await db
  .table("users")
  .where((q) => q.where("a", x).where("b", y))
  .orWhere((q) => q.where("c", z).orWhere("d", xx))
  .whereNot((q) => q.where("blocked", true))
  .get();

This reads as: (a = x AND b = y) OR ((c = z OR d = xx) AND NOT (blocked = true)). Use grouped callbacks whenever the exact parentheses matter.

Predicates

whereIn, whereNotIn, whereBetween, whereNotBetween, whereNull, whereNotNull, whereIs, whereIsNot

Use common predicate helpers for lists, ranges, null checks, and SQL IS tests.

Use predicates when the condition has a specific shape: membership, range, null, or boolean/null identity. They are clearer than manually writing the same logic with operators.

Example
const rows = await db
  .table("users")
  .whereIn("role", ["admin", "editor"])
  .whereBetween("created_at", start, end)
  .whereIsNull("deleted_at")
  .get();

This returns users whose role is either admin or editor, whose creation date is inside the range, and whose deleted_at value is null. In Mongo, these map to native operators like $in and range filters.

Quantified comparisons

whereAny, whereAll, orWhereAny, orWhereAll

Build ANY and ALL comparisons. Mongo supports literal arrays; SQL supports arrays and subquery/raw sources.

Use quantified comparisons when a value must compare against a set. ANY means the comparison can match at least one value. ALL means it must match every value.

Example
const rows = await db
  .table("users")
  .whereAny("score", ">", [10, 20, 30])
  .get();

This means score > ANY([10, 20, 30]): keep rows where score is greater than at least one value in the array. Use whereIn instead when you only need membership, such as role IN (...).

Joins

join, joinAs, joinOn, joinOnAs, innerJoin, leftJoin, rightJoin, innerJoinOn, leftJoinOn, rightJoinOn, innerJoinOnAs, leftJoinOnAs, rightJoinOnAs, andOn, orOn

Join tables or collections. In Mongo, joins compile to $lookup and $unwind; aliases become $lookup.as.

Use andOn(...) or orOn(...) after a join when the ON clause has multiple predicates. For MongoDB, put the current collection field first and the joined collection field second.

Example
const rows = await db
  .table("tickets")
  .leftJoinOnAs("users", "creator", "tickets.created_by", "creator.id")
  .leftJoinOnAs("users", "assignee", "tickets.assigned_to", "assignee.id")
  .select(["tickets.id", "creator.name", "assignee.name"])
  .get();
Multiple ON predicates
// LEFT JOIN A ON B.X = A.X AND B.Y = A.Y
const rows = await db
  .table("B")
  .leftJoinOn("A", "B.X", "A.X")
  .andOn("B.Y", "A.Y")
  .get();

Set operations

union, unionAll, clearUnions

Combine compatible select queries. Mongo supports QueryBuilder sources only.

Example
const q1 = db.table("users").select("id").where("active", true);
const q2 = db.table("admins").select("id").where("enabled", true);

const rows = await q1.unionAll(q2).get();

Mutations

insert, insertSelect, update, delete, returning

Build write operations. Use run() to execute mutations.

Example
const [post] = await db
  .table("posts")
  .insert({ title: payload.title, author_id: payload.authorId })
  .returning(["id", "title", "author_id"])
  .run();

Upsert helpers

onConflictDoUpdate, onDuplicateKeyUpdate

Use PostgreSQL-style conflict update or MySQL duplicate-key update. QueryMesh maps supported dialects where possible.

Example
await db
  .table("users")
  .insert({ email: "a@b.com", name: "Alice" })
  .onConflictDoUpdate("email", { name: "Alice" })
  .run();

Result controls

groupBy, having, orderBy, limit, offset

Control grouping, aggregate filters, ordering, and pagination.

Example
const page = await db
  .table("posts")
  .where("status", "published")
  .orderBy("created_at", "desc")
  .offset(20)
  .limit(10)
  .get();

Execution

compile, run, get, first

Compile without executing, execute mutations, fetch many rows, or fetch one row.

Example
const compiled = db.table("users").where("id", 1).compile();
const rows = await db.table("users").get();
const first = await db.table("users").where("id", 1).first();

SchemaBuilder

SchemaBuilder handles DDL and introspection. Start with db.schema().

Tables

createTable, alterTable, dropTable, renameTable

Create and modify SQL tables. Mongo currently maps dropTable to collection drop.

Example
await db.schema().createTable("posts", (t) => {
  t.bigInt("id").primary();
  t.string("title", 200).notNull();
  t.text("body");
  t.timestamps();
}).exec();

Databases and schemas

createDatabase, dropDatabase, showDatabases, createSchema, dropSchema

Create/drop databases where supported, list databases, and manage PostgreSQL schemas.

Example
await db.schema().createDatabase("analytics", { ifNotExists: true }).exec();
const names = await db.schema().showDatabases();

Views

createView, dropView

Create and drop SQL views. MongoDB views are not supported by QueryMesh schema APIs.

Example
const active = db.table("users").select(["id", "email"]).where("active", true);

await db.schema()
  .createView("active_users", active, { orReplace: true })
  .exec();

Triggers

createTrigger, dropTrigger

Create/drop triggers for SQL dialects. MongoDB triggers are not supported in QueryMesh.

Example
await db.schema().createTrigger({
  name: "trg_users_touch",
  table: "users",
  timing: "before",
  events: ["update"],
  body: "NEW.updated_at = CURRENT_TIMESTAMP;",
}).exec();

Introspection

showTables, showDatabases, getDesc(target?, opts?), exec

List tables/databases and return normalized table/database structure. includeCreateSql can include formatted creation scripts where supported.

Example
const tables = await db.schema().showTables();

const tableDesc = await db.schema().getDesc("users", {
  strict: true,
  includeCreateSql: true,
});

const dbDesc = await db.schema().getDesc("database", {
  deep: true,
  includeViews: true,
});

BaseModel

A light ORM layer over QueryBuilder. Bind models with db.model(ModelClass).

Static API

bind, query, find, all, create, where, hydrate

Define a model class with table and primaryKey, then use static helpers.

Example
import { BaseModel } from "querymesh";

class User extends BaseModel {
  static table = "users";
  static primaryKey = "id";
}

const UserModel = db.model(User);

const user = await UserModel.create({ email: "a@b.com" });
const found = await UserModel.find(1);
const admins = await UserModel.where("role", "admin");

Instance API

save, delete

Persist or delete hydrated model instances.

Example
const user = await UserModel.find(1);

user.email = "new@example.com";
await user.save();

await user.delete();

BackupManager

BackupManager wraps native CLI tools and exposes progress events. Start with db.backup().

export(options?)

export(options?: BackupExportOptions): BackupJob

Exports a database, schema, or selected tables using the current dialect tooling.

Example
const job = db.backup().export({
  file: "backup.dump",
  format: "custom",
  tables: ["users", "posts"],
});

job.on("progress", (e) => console.log(e.percent));
await job.done;

import(options?)

import(options?: BackupImportOptions): BackupJob

Imports or restores from a file/directory/archive where the dialect tooling supports it.

Example
const job = db.backup().import({
  file: "backup.dump",
  format: "custom",
});

job.on("log", (e) => console.log(e.line));
await job.done;
Backup jobs emit start, progress, log, error, and done. They also expose done as a promise and abort().

getAllToolingStatus() Returns status for all supported dialect toolchains. tools.getAllToolingStatus()
getCurrentDialectCliVersion() Returns the main CLI version for the current dialect. tools.getCurrentDialectCliVersion()

getDiagnostics() Returns dialect, ping, server version, and CLI status. await tools.getDiagnostics()

const tools = db.tools();

const ok = await tools.ping();
const version = await tools.getVersion();
const diagnostics = await tools.getDiagnostics();
